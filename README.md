# Group Scene Director

An extension that lets an OpenAI-compatible **"director" model decide who speaks next**
in group chats, using native OpenAI-style **function tool calls**, instead of
SillyTavern's talkativeness / mention / list-order dice rolls.

SillyTavern still runs **every actual generation**: character cards, prompt
assembly, depth prompts, the group nudge, streaming, and its own (optional)
native tool-calling loop are all untouched.

## How it works

Turn flow (chained mode, default):

```
you send a message
  └─ extension runs a tiny "director" request
       tool call: scene_director({ next_speaker: "<avatar>: Alice", reasoning: "..." })
  └─ extension temporarily rewrites the group roster (in memory only):
        members reordered, non-picked muted, activation_strategy = LIST
  └─ SillyTavern's generateGroupWrapper() activates exactly that roster
       → Alice's real reply is generated by ST (full prompts, cards, tools)
  └─ extension restores the group data instantly (before prompts are built)
  └─ extension probes again (sees Alice's reply):
       scene_director({ next_speaker: "<avatar>: Bob", reasoning: "rebuttal" })
       → run generateGroupWrapper({ force_chid: bobId }) → Bob replies
       scene_director({ next_speaker: "END_TURN" })
       → turn ends
```

Modes:

- **Chained (default)** - decide *after every reply*. Supports scenes like
  `user → char1 → char2 → char1` from a single user message. Each decision sees
  the conversation including the newest reply.
- **Batch** - queue the whole turn's speakers up front (cheaper, fixed order).

## Installation

Requires a recent SillyTavern (staging or release) with third-party extensions.

**Option A - Install extension box (easiest)**

In SillyTavern open the **Extensions** panel (magic wand menu) → **Install extension**
and paste:

```
https://github.com/thijsi123/ST-Group-Scene-Director
```

Reload the page afterwards.

**Option B - manual clone**

```bash
cd SillyTavern/public/scripts/extensions/third-party
git clone https://github.com/thijsi123/ST-Group-Scene-Director
```

Then hard-reload SillyTavern (Ctrl+F5). The extension appears in the Extensions
panel as **Group Scene Director**.

Quick check that tool calling works with your setup: open the extension settings
→ **Test & Debug** → **Test tool calling**.

## Requirements

- A group chat whose members can reply.
- An API model that supports **function calling** for the director request
  (OpenAI, Custom OpenAI-compatible, Mistral, Groq, DeepSeek, xAI, Google, ...).
  The director is a separate small request and does **not** need SillyTavern's
  own "Function calling" toggle - but the underlying API/model must support
  `tools` / `tool_choice`.
- **Enough token budget and time for the director.** Reasoning models spend
  tokens on their thinking trace *before* they emit the tool call; with too small
  a budget the answer comes back truncated (`finish_reason: "length"`) with no
  tool call - and a long trace also overruns a short request timeout. Both look
  exactly like "the model can't call tools". The defaults are 1500 tokens and a
  60 s timeout, and the extension automatically retries once with three times the
  budget when it detects a truncated answer. If the log still shows `length`,
  raise **Max tokens** further.

## Settings

- **Enable** - master switch (also `/director on|off`).
- **Selection mode** - chained / batch (default when the group does not
  override it).
- **Batch roster size** - how many speakers batch mode may queue per turn.
  Recursion uses the per-group limit instead (see below).
- **May override activation strategies** - Natural, Pool, List order, Manual.
  Strategies you leave off keep SillyTavern's stock behavior.
- **Same character may speak twice** - Never / Always / follow the group's
  "Self responses" toggle.
- **Show decisions** - hidden (console only), toast, or small system message.
- Director request: **tool choice** (forced `tool_choice` vs `auto`),
  temperature, max tokens, timeout, retries, and fallback behavior:
  - *If the director fails*: **on** (default) = SillyTavern's normal activation
    picks the speaker for that turn; **off** = the extension picks a random
    enabled member. Either way the turn always gets **exactly one** fallback
    speaker - the extension never leaves a group with an empty activation,
    because SillyTavern would then post an empty *user* message into the chat.
- Context & members: how many recent chat messages the director sees, message
  character limit, and whether the roster includes short descriptions per member.
- Advanced: delay between chained replies, extra instructions for the director
  prompt (supports macros like `{{user}}`, plus `{{roster}}`, `{{justSpoke}}`,
  `{{latestUserMessage}}`).
- `/director debug` dumps the last request payload + decision to the console.

## Group edit panel additions

The extension injects extra controls into the **group edit panel** (next to
"Allow self responses" / "Auto Mode") and one new entry into the
**Group reply strategy** select:

- **Reply strategy "Scene Director (recursive)"** - a UI alias. Selecting it turns
  on the per-group director flag and stores a stock strategy (*Natural order*)
  next to it. This matters: a raw strategy value the core does not know would
  make SillyTavern find nobody to activate and post an **empty user message**
  whenever the extension is not steering that particular turn (auto mode,
  extension switched off, failed probe, manual "speak" clicks). Legacy groups
  that stored the old value are migrated automatically the next time the group
  panel is opened.
  Picking any other strategy + enabling the override checkboxes works as well.
- **Scene Director: Recursive** *(checkbox)* + numeric input:
  - checked = chained/recursive scenes (probe → reply → probe …); unchecked =
    batch-style single decision per turn. Until you touch it, the group simply
    follows the global **Selection mode** setting.
  - the number is the **recursion limit** - how many AI replies one send may
    produce, `0` = unlimited (hard-capped at 50 for safety).
- **Full recursive** *(checkbox)* - the director is not allowed to end the turn
  early: it must keep picking speakers until the recursion limit is reached
  (`0` = keep going until stopped; the Stop button always works). Without it,
  the director may end turns at its own discretion once the limit allows.

## Test & Debug (extension drawer)

The settings panel has a **Test & Debug** section:

- **Test tool calling** - sends a minimal forced-tool-call request to the
  current API/model and reports PASSED/FAILED. Verifies the backend actually
  returns `tool_calls` before you try it in a real scene.
- **Live log** - read-only textbox with timestamps showing turn starts, roster
  application, each director probe, raw model output (text or tool-call JSON),
  errors, retries, group settings saves and chain progress. Nothing is written
  into the roleplay chat itself.

## Known limitations

- **A group set to the "Scene Director (recursive)" reply strategy needs this
  extension switched on** to actually be director-driven. Because the option is
  stored as a director flag + *Natural order*, such a group degrades gracefully
  into a stock Natural-order group instead (see above) - it never posts an empty
  user message.
- **Auto-mode** turns (the periodic "continue chat" timer) are not directed -
  they bypass user-triggered generation. Manual sends and group swipes behave stock.
- The temporary roster swap briefly mutes non-selected members *before the
  wrapper computes activation*. This is restored right after (before prompts are
  built), so APPEND-generation_mode groups are unaffected.
- Character avatars must not contain the text `": "` (used as separator in the tool
  enum; virtually never the case for PNG avatar filenames).
